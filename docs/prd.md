## 1. 项目简介
hashtag-genius 是一款致力于自动化采集、分析和归档多平台（如 TikTok、Instagram、Facebook、Reddit 等）热门话题标签（hashtag）的SaaS产品/数据服务。它旨在为内容创作者、营销人员、数据分析师和品牌方提供最新、最全面以及历史的标签数据支持，赋能其内容传播、营销决策和市场洞察。

## 2. 产品愿景
hashtag-genius 致力于成为全球领先的多平台热门话题标签采集、分析与智能推荐平台。我们希望通过精准的数据和智能的分析，赋能内容创作者抓住流量密码、助力品牌方制定高效营销策略、辅助数据分析师洞察社交趋势，最终实现内容传播与营销决策的智能化和高效化。

## 3. 用户画像

*   **内容创作者 (KOLs, KOCs, 自媒体人):**
    *   **需求:** 关注流行趋势，优化内容标签以提升曝光量和互动率；寻找内容创作灵感。
    *   **痛点:** 手动追踪各平台热点耗时耗力；难以判断标签的真实热度和潜力。
*   **品牌/营销人员 (企业市场部, 广告代理):**
    *   **需求:** 洞察市场热点和行业趋势；制定有效的标签营销策略；监控竞品标签动态；评估营销活动效果。
    *   **痛点:** 跨平台数据分散，难以整合分析；缺乏有效的工具来预测趋势和衡量标签影响力。
*   **数据分析师/研究者 (市场研究机构, 学术研究人员):**
    *   **需求:** 分析社交平台话题演变规律；挖掘用户兴趣和行为模式；获取结构化的历史标签数据进行研究。
    *   **痛点:** 历史数据获取困难；数据清洗和标准化工作量大。
*   **媒体/MCN机构 (内容分发平台, 创作者孵化机构):**
    *   **需求:** 快速追踪行业热点，指导内容生产方向；优化内容分发策略，提升旗下创作者影响力。
    *   **痛点:** 依赖人工经验判断热点，时效性差；难以规模化地为众多创作者提供标签建议。

## 4. 典型应用场景

*   **新媒体运营优化:** 内容创作者登录平台，查看其关注领域的最新热门标签榜单，选择合适的标签组合发布内容，提升帖子在 TikTok、Instagram 上的可见度。
*   **品牌营销活动策划:** 某快消品牌营销经理使用 hashtag-genius 分析近期食品饮料行业的热门标签和用户讨论焦点，结合其新产品特性，策划了一场名为 `#夏日清爽挑战` 的标签活动，并监控活动标签的传播效果。
*   **竞品分析与策略调整:** 科技公司的市场分析师订阅了竞品标签动态提醒，当竞争对手发起新的标签活动或其品牌标签热度显著变化时，能及时收到通知并分析其策略，调整自身推广方案。
*   **行业趋势研究报告:** 市场研究员利用 hashtag-genius 导出的历史标签数据（如过去一年内“可持续时尚”相关标签的演变），结合平台提供的趋势图，撰写关于消费者环保意识变化的行业报告。
*   **舆情监控与危机预警:** 大型企业通过 API 接入 hashtag-genius，实时追踪与其品牌或行业相关的敏感负面标签，一旦出现异常热度，系统自动告警，帮助公关团队及时响应。
*   **内容创作灵感获取:** MCN 机构的内容策划团队，通过浏览多平台的热门标签和趋势解读，为旗下创作者提供源源不断的内容创作方向和选题建议。

## 5. 核心功能

### 5.1. 数据采集
*   **多平台覆盖:**
    1.  TikTok
    2.  Instagram
    3.  Facebook (公开群组/页面热门话题)
    4.  Reddit (热门 Subreddits 讨论趋势)
    5.  X (Twitter) (趋势话题)
    6.  (未来可扩展) YouTube, Pinterest, LinkedIn 等。
*   **数据来源策略:**
    1.  **实时/准实时热门发现:**
        *   通过监测各平台官方或非官方的“趋势”、“热门”、“探索”等板块。
        *   利用 Google 等搜索引擎趋势工具（如 Google Trends API，或通过搜索特定关键词组合如 "trending hashtags tiktok today"）发现指示性信息，再辅以直接验证。
        *   监控行业媒体、KOL发布的趋势报告，作为线索来源。
    2.  **历史数据归档:**
        *   利用 archive.org (Wayback Machine) 获取各平台历史页面快照中的标签数据。
        *   逐步积累自身采集的每日数据，形成自有历史数据库。
    3.  **API 优先:** 若平台提供公开的、允许获取趋势标签的 API，则优先使用官方 API。
*   **采集频率:**
    *   热门标签：高频采集（例如：每小时或每数小时，根据平台特性调整）。
    *   历史数据：根据 archive.org 更新频率及自身归档策略执行。

### 5.2. 数据处理流程
*   **原始数据清洗:** 去除无关字符、格式化。
*   **去重处理:** 基于 hashtag 文本和来源平台，确保标签的唯一性（同一时间窗口内）。
*   **标准化:** 统一标签格式（如全部小写，去除特殊符号等，根据平台特性决定是否保留）。
*   **数据丰富:** 补充元数据，如采集时间、来源平台、来源类型（实时抓取/历史归档）、相关链接（指向该标签在对应平台的搜索结果页或趋势来源页）。
*   **每日新增追加:** 将当日新采集的、去重后的标签数据追加到主数据集。
*   **历史归档:** 将每日的全量数据或增量数据定期归档到历史数据库/文件中。
*   **大文件切分:** 当单个数据文件（如 JSON）超过预设阈值（如 100MB 或 100万条记录），自动按日期或序列号进行切分，以提升读写和处理效率。
*   **多平台数据整合:** 支持将不同平台采集的标签数据存储在统一的结构中，或按平台分别存储但提供统一的查询接口。

### 5.3. 数据文件结构与命名规范
*   **核心数据结构 (示例 JSON 记录):**
    ```json
    {
      "hashtag": "string",         // 标签文本 (已标准化)
      "platform": "string",        // 来源平台 (e.g., "TikTok", "Instagram")
      "timestamp_collected": "ISO8601_datetime", // 数据采集的UTC时间戳
      "source_type": "string",     // 来源类型 (e.g., "realtime_scrape", "archive_org", "api")
      "source_url": "string",        // 原始数据来源链接或API端点 (如有)
      "discovery_url": "string",   // (可选) 发现该标签为热门的线索链接 (如Google搜索结果页)
      "estimated_posts": "integer",// (可选) 相关帖子数量估算 (若可获取)
      "trend_score": "float",      // (可选) 内部计算的热度分值
      "first_seen_trending": "ISO8601_datetime", // (可选) 首次发现该标签热门的时间
      "category_tags": ["string"]  // (可选, 未来AI分析) 标签的分类 (e.g., "travel", "food", "challenge")
    }
    ```
*   **数据文件命名规范:**
    *   **实时/最新数据 (每日聚合):** `{prefix}-{platform}-latest-{YYYYMMDD}.json` (e.g., `htgenius-tiktok-latest-20231027.json`)
    *   **历史归档数据 (按日):** `{prefix}-{platform}-archive-{YYYYMMDD}.json` (e.g., `htgenius-instagram-archive-20231027.json`)
    *   **切分文件:** `{prefix}-{platform}-{type}-{YYYYMMDD}-part{N}.json` (e.g., `htgenius-reddit-latest-20231027-part1.json`)
    *   `{prefix}`: 可自定义，默认为 `htgenius`。
    *   `{type}`: `latest` 或 `archive`。
    *   文件格式初期为 JSON，未来可支持 CSV 导出或直接存储于数据库。

### 5.5. 数据分析与智能推送

#### 5.5.1. 数据分析能力
*   **趋势分析:** 基于时间序列数据，识别标签的上升、下降、周期性爆发等趋势。
*   **热点预测:** (高级功能) 结合历史数据、增长速率、外部事件等因素，尝试预测未来可能爆火的标签。
*   **标签热度排行:** 提供各平台、各分类（如适用）下的标签热度排行榜。
*   **跨平台对比分析:** 分析同一话题或相似标签在不同平台的表现差异。
*   **用户画像关联分析 (间接):** 分析特定类型标签（如 #美食探店 vs #科技测评）主要在哪些平台流行，间接反映不同平台用户群的兴趣偏好。**注意：不直接分析用户 PII。**
*   **标签生命周期分析:** 识别标签从出现、增长、成熟到衰退的各个阶段。

#### 5.5.2. 分析方法
*   **时间序列分析:** ARIMA, Prophet 等模型用于趋势预测和季节性分析。
*   **统计分析:** 计算增长率、波动率、相关性等。
*   **自然语言处理 (NLP - 未来):** 对标签本身进行语义分析、情感分析（若结合相关内容）、主题建模。
*   **网络分析 (未来):** 分析标签之间的共现关系，构建标签图谱。
*   **机器学习 (未来):** 用于热点预测、标签分类、智能推荐等。

#### 5.5.3. Newsletter 推送 (详细)

*   **A. 目标 (Objectives):**

            1.  **本周热门标签概览:** 精选主流平台（如TikTok, Instagram）最热门的通用标签 (Top 3-5/平台)，简述热度及趋势 (↑ 🔥 ↓)。
            2.  **趋势简析:** 对1-2个特别值得关注的标签或现象进行简要解读 (100-200字)。
            3.  **平台亮点/教程:** 介绍平台一个核心功能或使用技巧。
            4.  **内容灵感 (Teaser):** 提供1-2个基于当前趋势的通用内容创作方向。

    *   **II. 高级版/定制化 Newsletter (Premium Tier - 针对付费用户):**
        *   **频率:**
            *   标准版: 每周一次 (内容更深度)。
            *   可选: 每日热点速递 (针对高时效性需求用户)。
        *   **核心内容:**
            1.  **个性化热门标签报告:** 基于用户预设关注平台及行业/领域（如美妆、科技、游戏），展示Top 10-20热门标签，含热度值、增长率、相关内容量估算。

            3.  **竞品/行业标签动态 (如用户配置):** 推送关注竞品或特定行业关键词相关标签动态。
            4.  **专属内容策略建议:** 基于行业和目标受众，提供具体标签组合和内容创作方向。
            5.  **新功能/高级功能教程:** 详细介绍高级功能使用技巧。
            6.  **行业专属报告摘要/链接:** 优先获得平台产出的深度分析报告。

    *   **数据源:** hashtag-genius 核心数据库和分析模块。

    *   **AI/LLM 辅助 (未来):** V1规则+人工，V2 AI辅助生成分析初稿，人工审核。
    *   **审核机制:** 自动化生成后，运营/编辑人员审核，确保质量。

*   **D. 推送机制与个性化 (详见 5.5.5.)**

*   **E. 效果追踪与优化:**
    *   **关键指标:** 送达率、打开率、点击率 (CTR)、转化率、退订率。
    *   **分析工具:** ESP 自带分析，Google Analytics。
    *   **A/B 测试:** 主题行、内容布局、CTA、发送时间。
    *   **用户反馈:** 收集用户对内容的反馈。

#### 5.5.4. 用户分层服务
*   **潜在用户/免费用户:**
    *   可访问部分热门标签数据（如 Top N，有限平台）。

#### 5.5.5. 推送机制
*   **渠道:**
    *   **邮件 (Email):** 主要渠道。集成 SendGrid, Mailgun, Amazon SES 等专业 ESP。
    *   **Webhook:** (付费/企业用户) 将 Newsletter 核心数据或特定告警推送到用户指定系统 (Slack, Teams, 自定义端点)。
    *   **应用内通知 (In-App Notifications):** (未来) 在平台内推送重要更新或个性化提醒。
*   **订阅管理:** 用户可在个人设置中管理订阅偏好（频率、内容类型、渠道）。清晰的退订机制。
*   **频率自定义:** 用户可选择接收 Newsletter 的频率（如每日、每周、每月，或关闭）。

#### 5.5.6. 智能推荐
*   **基于用户画像:** 根据用户注册时选择的行业、关注的平台等信息。
*   **基于行为数据:** 分析用户在平台内常搜索的标签、常查看的报告、保存的偏好设置。
*   **动态调整推送内容:** 结合上述信息，动态调整 Newsletter 和应用内推荐的标签及分析内容，实现精准触达。
*   **例如:** 如果用户经常搜索与“健身”相关的标签，系统会优先推送健身领域的新兴热门标签和相关分析。

## 6. 技术实现

### 6.1. 技术栈
*   **后端/脚本语言:** Python (Scrapy, BeautifulSoup, Requests, Pandas, FastAPI/Flask) 和/或 Node.js (Puppeteer/Playwright, Cheerio, Express.js)。
*   **数据存储:**
    *   **初期/轻量级:** JSON 文件，存储于 Git 仓库 (如 GitHub/GitLab) 或对象存储 (AWS S3, Google Cloud Storage)。
    *   **规模化/分析需求:**
        *   **关系型数据库:** PostgreSQL (优良的 JSONB 支持，适合结构化元数据和用户数据)。
        *   **NoSQL数据库:** Elasticsearch (强大的搜索和聚合分析能力，适合标签索引和趋势分析)、MongoDB。
        *   **时序数据库:** InfluxDB, TimescaleDB (若需对标签热度等时间序列数据做精细化高性能分析)。
*   **前端框架:** React, Vue.js, or Angular。
*   **数据可视化库:** D3.js, Chart.js, ECharts, Plotly Dash。
*   **CI/CD 与自动化:** GitHub Actions, GitLab CI, Jenkins。
*   **容器化 (可选):** Docker, Kubernetes (用于部署和扩展)。
*   **消息队列 (可选):** RabbitMQ, Kafka (用于解耦采集、处理、通知等任务)。
*   **邮件服务:** SendGrid, Mailgun, Amazon SES (用于 Newsletter 和告警)。

### 6.2. 自动化与配置
*   **Prefix 可配置化:** 支持通过配置文件或环境变量自定义数据文件/数据库表前缀。
*   **平台可配置化:** 通过配置文件（如 `config.yaml` 或 JSON）指定需要采集的平台列表及其特定参数（如目标URL、采集频率）。
*   **采集策略可配置:** 针对不同平台、不同类型数据（实时/历史）可配置采集频率、深度等。
*   **CI/CD 自动化采集与提交:**
    *   使用 GitHub Actions 等工具设置定时任务 (cron jobs)。
    *   定时触发数据采集脚本。
    *   脚本执行完毕后，自动处理数据、生成文件。
    *   自动将更新的数据文件 commit 并 push 到 Git 仓库，或同步到数据库/对象存储。
    *   实现无人值守的数据更新流程。

### 6.3. 可扩展性
*   **架构设计:** 采用模块化设计，各功能模块（采集、处理、分析、API、前端）松耦合，便于独立升级和扩展。
*   **新增采集渠道:** 设计通用的采集器接口或基类，方便快速适配和添加新的社交平台或数据源。
*   **自定义数据字段:** 数据库模式或文件结构应预留扩展空间，便于未来增加新的分析维度或元数据。
*   **水平扩展:** 后端服务和数据采集器可设计为无状态或易于水平扩展的，以应对更高的并发和数据量。
*   **API 驱动:** 核心功能通过内部 API 提供，便于未来不同客户端（Web, App, 第三方）的接入。

## 7. 数据管理与质量

### 7.1. 数据质量保障
*   **多源校验:** 对从不同渠道获取的同一标签信息进行交叉验证（如适用）。
*   **数据清洗与去重:** 严格的去重逻辑，保证数据的准确性和唯一性。
*   **格式校验:** 确保采集的数据符合预定义的格式和类型。
*   **定期脚本有效性检测:**
    *   监控采集脚本的成功率和数据获取量。
    *   当平台网站结构变更导致脚本失效时，能及时发现。
    *   建立快速响应机制，修复或更新采集脚本。
*   **数据完整性校验:** 定期检查数据是否存在缺失或异常。
*   **异常数据报警机制:** 当采集到的数据出现明显异常（如数量突增/突降、格式错误）时，自动触发告警。
*   **人工抽检与反馈回路:** 定期人工抽查数据质量，并根据用户反馈持续优化数据处理逻辑。

### 7.2. 数据安全与合规
*   **遵守平台政策:**
    *   严格遵守各社交平台的数据使用政策 (Terms of Service)、开发者协议和 `robots.txt` 规定。
    *   优先使用官方公开 API (如果提供并符合需求)。
    *   对于抓取，采取友好的抓取策略：合理的请求频率、设置 User-Agent、避免对目标服务器造成过大压力。
*   **公开数据采集:** 明确只采集和分析公开可获得的数据，不涉及用户隐私数据。
*   **数据脱敏与匿名化:** 如果在处理过程中可能间接接触到任何可能识别个人的信息，应进行脱敏或匿名化处理。
*   **数据存储安全:**
    *   对敏感配置信息（如 API Keys）加密存储。
    *   数据库访问权限控制。
    *   定期数据备份。
*   **数据访问日志与权限控制:** (针对平台用户) 记录用户的数据访问和操作行为，实施基于角色的访问控制 (RBAC)。
*   **合规性声明:** 在产品网站和服务条款中明确数据来源、使用方式及合规性承诺。
*   **GDPR/CCPA 等法规考量:** 针对目标用户所在地的隐私法规，确保数据处理流程合规。

### 7.3. 异常监控与告警
*   **监控范围:**
    *   **采集任务失败:** 脚本执行错误、网络问题、目标平台反爬。
    *   **数据量异常:** 采集到的数据条目远低于或远高于预期。
    *   **数据格式错误:** 解析出的数据不符合预设结构。
    *   **平台接口/结构变更:** 导致采集逻辑失效。
    *   **API 调用错误/超限:** 使用第三方 API 时的错误。
    *   **系统资源:** 服务器 CPU、内存、磁盘使用率。
*   **告警机制:**
    *   **实时告警:** 发生严重错误时立即通知。
    *   **汇总报告:** 定期发送监控摘要。
*   **通知渠道:**
    *   邮件
    *   Webhook (如推送到 Slack, PagerDuty, Teams)
    *   短信 (针对高级别告警，可选)
*   **日志管理:**
    *   详细记录采集过程、数据处理、错误信息。
    *   结构化日志，便于查询和分析 (如 ELK Stack, Grafana Loki)。
    *   采集日志可视化，便于快速定位问题。
*   **自动恢复尝试 (可选):** 对某些已知类型的瞬时错误（如网络抖动），可尝试自动重试。

## 12. 风险与挑战

*   **技术风险:**
    *   **平台反爬策略升级:** 目标社交平台不断更新其网站结构和反爬虫机制，导致采集脚本频繁失效。
        *   **缓解:** 采用多种采集技术组合（包括模拟浏览器行为），快速响应和更新脚本，研究使用代理IP池，关注平台开发者政策变化。
    *   **数据规模与性能瓶颈:** 随着数据量增长，存储、处理和查询性能可能下降。
        *   **缓解:** 选择可扩展的数据库方案，优化查询语句，引入缓存机制，对数据进行合理分片或归档。
    *   **API 限制与成本:** 若依赖第三方 API，可能面临调用频率限制、费用增加或 API 停用风险。
        *   **缓解:** 仔细阅读 API 文档，优化调用逻辑，准备备用数据源或采集方案。
*   **合规与法律风险:**
    *   **平台 ToS 冲突:** 数据采集行为可能被平台视为违反其服务条款。
        *   **缓解:** 严格遵守 `robots.txt`，优先使用官方 API，保持低调和友好的抓取行为，关注平台政策更新，必要时咨询法律意见。
    *   **数据隐私法规 (GDPR, CCPA 等):** 处理涉及个人信息的数据时（即使是公开的）可能触犯法规。
        *   **缓解:** 明确不采集个人身份信息 (PII)，对可能间接关联的数据进行匿名化处理，提供清晰的隐私政策。
*   **市场与竞争风险:**
    *   **竞争激烈:** 已有成熟的社交媒体分析工具提供部分类似功能。
        *   **缓解:** 聚焦于标签分析的深度和独特性，提供差异化价值（如更强的预测能力、更便捷的跨平台比较、更智能的推荐）。
    *   **用户需求变化:** 用户对标签分析的需求可能随社交媒体发展而变化。
        *   **缓解:** 保持对市场趋势的关注，积极收集用户反馈，快速迭代产品。
*   **数据质量与准确性风险:**
    *   **“热门”定义的主观性:** 不同平台、不同时间对“热门”的定义可能不同，难以完全客观量化。
        *   **缓解:** 透明化热度计算方法，允许用户自定义部分参数，结合多种指标综合判断。
    *   **数据噪音:** 采集到的数据中可能包含广告、spam 或不相关内容。
        *   **缓解:** 持续优化数据清洗和过滤算法，引入机器学习模型辅助识别噪音。

    *   持续引入 AI/LLM 模型优化分析与推荐。
    *   扩展更多平台和垂直领域支持。
    *   深化高级分析功能 (影响力评分、传播路径等)。
    *   完善插件生态。
    *   根据用户反馈和市场变化持续迭代。
